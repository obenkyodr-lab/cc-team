# cc-team

Claude Code上で動作するAI実務支援フレームワーク。
秘書エージェントを窓口として、複数のAIエージェントとスキルを組み合わせて業務を処理する。

---

## 1. cc-teamとは

日常業務をClaude Code上でAIに任せるための「仮想チーム」構造。  
ユーザーは秘書に依頼するだけでよく、以降の振り分け・処理はフレームワーク内で完結する。

---

## 2. 基本構造

```
ユーザー
  ↓ /aiteam コマンドで依頼
Secretary（窓口・振り分け）
  ↓ 依頼内容に応じてルーティング
Agents（判断・実行）
  ↓ 必要なスキルを呼び出す
Operations/SKILL（再利用可能な業務手順）
```

---

## 3. フォルダ説明

| フォルダ | 役割 |
|---|---|
| `secretary/` | 依頼を受け取り、適切なエージェントへ振り分ける窓口 |
| `agents/` | 判断主体となるエージェント群（抄録、スライドなど） |
| `operations/` | 再利用可能な業務スキル（SKILL.md）を格納 |
| `projects/` | 案件単位のコンテキストと管理情報 |
| `shared/` | プライバシールール・文体ガイドなど共通ルール |
| `plugin/commands/` | Claude Codeスラッシュコマンドのエントリーポイント |

---

## 4. 基本ワークフロー

1. Claude Codeのチャットで `/aiteam` コマンドを実行
2. 秘書エージェントが依頼内容を解析し、担当エージェントへ振り分け
3. エージェントが `operations/` 内のSKILLを呼び出して処理
4. 結果をユーザーへ返却

---

## 5. 設計思想

- **Secretary中心設計** — ユーザーは秘書だけに話しかければよい。複雑な振り分けはフレームワーク内部で処理される
- **エージェントは判断主体** — 各エージェントは「何をどう処理するか」を判断し、スキルを組み合わせて実行する
- **SKILLは業務手順の部品** — `operations/` 内のSKILLは独立した再利用可能な手順書。エージェントをまたいで使い回せる
- **プロジェクト単位の管理** — `projects/` で案件ごとのコンテキスト・成果物を管理し、継続作業に対応する
- **共通ルールの集約** — プライバシー・文体などのルールは `shared/` に集め、全エージェントが参照する
